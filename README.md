# Digital Support Chatbot (RAG)

แชทบอทสนับสนุนงานไอทีที่ตอบคำถามจาก **คู่มือการใช้งานระบบงานจริง** ด้วยเทคนิค
Retrieval-Augmented Generation (RAG) — เป็นส่วนสาธิต (prototype) ของสารนิพนธ์
"การพัฒนาแชทบอทสนับสนุนงานไอทีด้วยโมเดลภาษาขนาดใหญ่และเทคนิคการสร้างคำตอบแบบเสริมด้วยการค้นคืนข้อมูล"

ทุกขั้นตอนการค้นคืนใช้ pipeline **ชุดเดียวกับที่รายงานผลไว้ในสารนิพนธ์** ไม่ได้เขียนใหม่
สคริปต์สร้างดัชนี (`scripts/build_index.py`) เรียกฟังก์ชันตัด chunk จาก
`Model AI/lm_studio_eval/rag_eval_lmstudio.py` โดยตรง ฐานความรู้ของแชทบอทจึงเหมือน
กับที่ใช้ทดลองทุกประการ

## ระบบทำงานอย่างไร

```
คำถามผู้ใช้
   │
   ├─ 1) Metadata filter   ตรวจจับชื่อระบบงานในคำถาม แล้วจำกัดขอบเขตค้นเฉพาะเอกสารของระบบนั้น
   ├─ 2) Hybrid search     ค้นคู่ขนานด้วย dense embedding (multilingual-e5-base) + BM25
   │                       แล้วรวมอันดับด้วย Reciprocal Rank Fusion (RRF, k=60)
   ├─ 3) Reranker          จัดอันดับผู้สมัครซ้ำด้วย cross-encoder (bge-reranker-v2-m3) เลือก top-5
   │
   ├─ 4) ประกอบ prompt      แทรกเนื้อความที่ค้นได้เป็นบริบทใน system prompt
   └─ 5) LLM ตอบ            ผ่าน OpenAI-compatible API (LM Studio ในเครื่อง หรือ OpenRouter)
                            พร้อมส่งรายการเอกสารต้นทางกลับไปแสดงใต้คำตอบ
```

ถ้าโหลดดัชนีไม่สำเร็จ หรือตั้ง `RAG_ENABLED=false` แอปจะไม่ล้ม แต่จะกลายเป็นแชทบอททั่วไป
ที่คุยกับโมเดลตรงๆ (ใช้ `SYSTEM_PROMPT` จาก `.env`) — ใช้เปรียบเทียบ "มี RAG / ไม่มี RAG"
ตอนสาธิตได้เลย

```
scripts/serve.py         ตัวเปิดเซิร์ฟเวอร์ที่เขียน log ลงไฟล์ (ใช้โดย serve.ps1/service.ps1)
scripts/export_history.py ส่งออกประวัติเป็น CSV ไว้วิเคราะห์
scripts/export_chunks.py  แยกดัชนีเป็นไฟล์รายระบบงานที่คนอ่านได้
services/db.py           เก็บประวัติคำถาม-คำตอบลงฐานข้อมูล
data/                    ไฟล์สถานะของแอป — ไม่ควร commit
logs/                    log ของเซิร์ฟเวอร์ — ไม่ควร commit
rag_index/               ดัชนีที่สร้างไว้ (chunks.jsonl, embeddings.npy, meta.json) — ไม่ควร commit
requirements.txt         แพ็กเกจฝั่งเว็บอย่างเดียว (Vercel ใช้ไฟล์นี้)
requirements-rag.txt     แพ็กเกจครบชุดรวม RAG (ใช้ตอนรันในเครื่อง)
static/, templates/      หน้าเว็บ (HTML/CSS/JS) รวมกล่องแสดงแหล่งอ้างอิงใต้คำตอบ
api/index.py             entrypoint สำหรับ Vercel (ดูข้อจำกัดท้ายไฟล์)
```

## วิธีรัน

### 1. ติดตั้ง

```bash
python -m venv .venv
.venv\Scripts\activate           # macOS/Linux: source .venv/bin/activate

# ถ้าจะรัน LM Studio ไปพร้อมกัน ลง torch แบบ CPU ก่อน (เล็กกว่ามากและไม่แย่ง VRAM)
pip install torch --index-url https://download.pytorch.org/whl/cpu

pip install -r requirements-rag.txt
```

**แพ็กเกจแยกเป็นสองไฟล์** เพราะ Vercel จำกัดขนาด serverless function ไว้ที่ 500 MB
ส่วน torch + sentence-transformers รวมกันเกิน 5 GB

| ไฟล์ | ใช้เมื่อไหร่ |
|---|---|
| `requirements.txt` | เฉพาะตัวเว็บ ไม่มี RAG — เป็นไฟล์ที่ Vercel ใช้ตอน build |
| `requirements-rag.txt` | ครบทุกอย่างรวม RAG (มี `-r requirements.txt` อยู่ข้างในแล้ว) — ใช้ตอนรันในเครื่อง |

ถ้าจะรันเฉพาะโหมดแชทธรรมดา ติดตั้งแค่ `requirements.txt` แล้วตั้ง `RAG_ENABLED=false` ก็พอ

### 2. สร้างดัชนี (ทำครั้งเดียว)

```bash
python scripts/build_index.py
```

อ่านเอกสารจาก `Model AI/lm_studio_eval/knowledge_base/Applications/` แล้วเขียนดัชนีลง
`rag_index/` ครั้งแรกจะดาวน์โหลดโมเดล embedding จาก Hugging Face ก่อน (~1 GB)

ถ้าโครงสร้างโฟลเดอร์ต่างจากค่าเริ่มต้น ระบุ path เองได้:

```bash
python scripts/build_index.py --eval-script "D:/Project IS/Model AI/lm_studio_eval/rag_eval_lmstudio.py"
```

### 3. ตั้งค่า `.env` แล้วรัน

```bash
copy .env.example .env           # macOS/Linux: cp .env.example .env
uvicorn main:app --reload
```

เปิด http://127.0.0.1:8000 — ป้ายใต้หัวข้อจะบอกสถานะฐานความรู้ (กำลังโหลด / พร้อม / ปิดอยู่)
โหลดดัชนีครั้งแรกใช้เวลาสักครู่ ระหว่างนั้นหน้าเว็บเปิดใช้ได้ตามปกติ

## เพิ่มคู่มือหรือระบบงานใหม่เข้าฐานความรู้

### 1. วางไฟล์

```
Model AI/lm_studio_eval/knowledge_base/Applications/
    <ชื่อระบบงาน>/            <- ชื่อโฟลเดอร์ชั้นนี้คือชื่อระบบที่ขึ้นใน dropdown
        External/             <- โครงที่ใช้อยู่ (แยกเอกสารลูกค้า/ภายใน) ไม่บังคับ
        Internal/
```

**ชื่อโฟลเดอร์ชั้นบนสุดใต้ `Applications/` คือชื่อระบบงาน** โค้ดอ่านค่านี้ไปใช้เป็นทั้ง
ตัวเลือกใน dropdown และตัวกรอง metadata โฟลเดอร์ย่อยที่ลึกกว่านั้นไม่มีผลต่อชื่อระบบ
แค่กลายเป็นส่วนหนึ่งของ `doc_id` ที่แสดงในกล่องแหล่งอ้างอิง

เพิ่มโฟลเดอร์ระบบใหม่ได้เลย ไม่ต้องแก้โค้ดหรือ config — สร้างดัชนีใหม่แล้วมันจะโผล่ใน
dropdown เอง

**ชนิดไฟล์ที่อ่านได้:** `.pdf` `.docx` `.xlsx` `.msg` `.txt`
ชนิดอื่น (`.zip` `.rar` `.jpg` `.cer` ฯลฯ) ถูกข้ามเงียบๆ ไม่ทำให้ล้มเหลว

**สองอย่างที่ควรรู้**

- **ไฟล์ที่เหมือนกันทุกไบต์จะถูกข้ามอัตโนมัติ** (ยึดฉบับแรกตามลำดับชื่อไฟล์) เพราะหลายระบบ
  เก็บเอกสารชุดเดียวกันซ้ำทั้งใน `External/` และ `Internal/` — ในชุดปัจจุบันมีซ้ำแบบนี้ 45 ไฟล์
  จาก 143 ไฟล์ จึงไม่ต้องกังวลว่าวางซ้ำแล้วคำตอบจะเพี้ยน
- **PDF ที่สแกนมาเป็นรูปจะไม่ได้ข้อความเลย** เพราะไม่มี text layer ให้สกัด ระบบจะอ่านได้ 0 chunk
  จากไฟล์นั้นโดยไม่มี error แจ้ง ถ้าเพิ่มคู่มือแล้วถามไม่เจอ ให้สงสัยข้อนี้ก่อน — ลองเปิดไฟล์
  แล้วกด Ctrl+A ถ้าเลือกข้อความไม่ได้แปลว่าเป็นรูป ต้องแปลงด้วย OCR ก่อน

### 2. สั่งอัปเดต

```powershell
cd "D:\Project IS\GitHub\ChatBoT-CPN-Digital-Support"
.\update.ps1
```

คำสั่งเดียวจบ — สร้างดัชนีใหม่แล้วเปิดแอปต่อให้เลย ระหว่างทางจะพิมพ์ตัวเลขก่อน/หลัง
ให้เทียบว่าเอกสารใหม่เข้าไปจริงไหม

```
  before : 882 chunks / 102 docs / 17 systems
  after  : 950 chunks / 110 docs / 18 systems
  change : +68 chunks / +8 docs / +1 systems
```

ถ้าขึ้น `+0` ทุกช่องทั้งที่เพิ่งวางไฟล์ไป แปลว่าเอกสารไม่ได้เข้าดัชนี — สาเหตุที่พบบ่อยคือ
นามสกุลไม่รองรับ, ไฟล์ซ้ำกับที่มีอยู่แล้วทุกไบต์, หรือเป็น PDF สแกนที่ไม่มี text layer

สคริปต์**สร้างใหม่ทั้งหมดทุกครั้ง** ไม่ได้เพิ่มเฉพาะไฟล์ใหม่ จึงใช้เวลาเท่ากับรอบแรกเสมอ
(โมเดลอยู่ในแคชแล้ว ไม่ต้องดาวน์โหลดซ้ำ) ถ้า build ล้มเหลว ดัชนีเดิมจะไม่ถูกแตะต้อง

`update.ps1` ยัง**สร้างไฟล์อ่านได้ใน `rag_index/by_system/` ให้ใหม่ทุกครั้ง**ด้วย
จะได้ไม่เผลออ่านของเก่าที่ไม่ตรงกับดัชนีปัจจุบัน

ตัวเลือกเพิ่มเติม

```powershell
.\update.ps1 -NoRun        # สร้างดัชนีอย่างเดียว ไม่เปิดแอปต่อ
.\update.ps1 -NoExport     # ไม่ต้องสร้างไฟล์อ่านได้ใหม่
.\update.ps1 -Port 8001    # ส่ง port ต่อให้ run.ps1
```

> ต้องรีสตาร์ทแอปเสมอหลังสร้างดัชนีใหม่ เพราะแอปอ่านดัชนีเข้าหน่วยความจำตอนเปิด
> ครั้งเดียว ไม่ได้เฝ้าดูไฟล์ — `update.ps1` จัดการให้แล้ว

## รันเบื้องหลัง (ไม่ต้องค้างหน้าต่างคอนโซล)

`run.ps1` ยึดหน้าต่างไว้แสดง log ปิดหน้าต่างเมื่อไหร่เซิร์ฟเวอร์ก็ดับ ถ้าต้องการให้รันค้างไว้
ใช้ `serve.ps1` แทน

```powershell
.\serve.ps1 start          # เปิดเบื้องหลัง แล้วเปิดเบราว์เซอร์ให้
.\serve.ps1 status         # ดูว่ารันอยู่ไหม pid อะไร rag/db พร้อมหรือยัง
.\serve.ps1 logs -Follow   # ดู log สดๆ (Ctrl+C ออกได้ ไม่กระทบเซิร์ฟเวอร์)
.\serve.ps1 restart
.\serve.ps1 stop
```

เบื้องหลังใช้ `pythonw.exe` ซึ่ง**ไม่สร้างหน้าต่างคอนโซลเลย** ปิดเทอร์มินัลได้ เซิร์ฟเวอร์
ยังทำงานต่อ ผลข้างเคียงคือไม่มี stdout/stderr ให้เขียน log — `scripts/serve.py` จึงตั้ง
logging ให้เขียนลง `logs/server.log` เอง (หมุนไฟล์ที่ 5 MB เก็บย้อนหลัง 5 ไฟล์)

สถานะเก็บไว้ที่ `data/server.pid` และ `data/server.port` คำสั่ง stop/status จึงหาโปรเซสเจอ
แม้จะปิดหน้าต่างที่สั่ง start ไปแล้ว และถ้าโปรเซสตายไปเอง ไฟล์ pid ค้างจะถูกล้างให้อัตโนมัติ

### ถ้าต้องการให้เริ่มเองตอนบูตเครื่อง

`serve.ps1` พอสำหรับใช้งานทั่วไป แต่ไม่เริ่มเองหลังรีสตาร์ทเครื่อง ถ้าต้องการระดับนั้นให้ติดตั้ง
เป็น Windows service ด้วย [NSSM](https://nssm.cc)

```powershell
winget install NSSM.NSSM        # ครั้งเดียว แล้วเปิดเทอร์มินัลใหม่
# จากนั้นเปิด PowerShell แบบ Run as administrator
.\service.ps1 install
.\service.ps1 start
.\service.ps1 status
```

ได้เพิ่มมาคือเริ่มเองตอนบูต (ก่อนล็อกอินด้วย) Windows รีสตาร์ทให้ถ้าแอปแครช และจัดการ
ผ่าน `services.msc` ได้

> ใช้ NSSM แทนการเขียน service ด้วย pywin32 เพราะ uvicorn ติดตั้ง signal handler ตอนปิด
> ซึ่งทำงานได้เฉพาะใน main thread — รันในคลาส service ของ pywin32 แล้วมักพังด้วย
> `signal only works in main thread of the main interpreter` ส่วน NSSM คุมโปรเซสจาก
> ภายนอก เลยไม่เจอปัญหานี้เลย

## เก็บประวัติคำถาม-คำตอบ

ทุกรอบถาม-ตอบถูกบันทึกลงฐานข้อมูล เปิดใช้อยู่แล้วโดยค่าเริ่มต้น (`DB_ENABLED=true`)
ฐานข้อมูลที่ใช้คือ **PostgreSQL** (เดิมเป็น SQLite ไฟล์เดียว ย้ายมาเพราะต้องรองรับผู้ใช้
หลายคนเขียนพร้อมกัน และให้ทีมอื่นดึงข้อมูลไปวิเคราะห์จากเครื่องอื่นได้)

### ติดตั้ง PostgreSQL ครั้งแรก (Windows)

1. ดาวน์โหลดตัวติดตั้งจาก <https://www.postgresql.org/download/windows/> (EDB installer)
   เลือกเวอร์ชัน 16 ขึ้นไป
2. ระหว่างติดตั้ง **จดรหัสผ่านของผู้ใช้ `postgres` ไว้** — ใช้ตอนรันสคริปต์เตรียมฐานข้อมูล
   ส่วนประกอบที่จำเป็นมีแค่ *PostgreSQL Server* กับ *Command Line Tools*
   (pgAdmin ติดตั้งด้วยก็ได้ถ้าอยากมีหน้าจอดูข้อมูล) พอร์ตปล่อยเป็น 5432 ตามค่าเริ่มต้น
3. ตรวจว่าเซอร์วิสทำงานอยู่ — เปิด `services.msc` หา `postgresql-x64-16` ต้องขึ้น *Running*

### ตั้งค่าและสร้างฐานข้อมูล

ตั้งค่าใน `.env` (คัดลอกจาก `.env.example`) — ตั้ง `POSTGRES_PASSWORD` เป็นรหัสผ่าน
ที่ต้องการให้ผู้ใช้ของแอปใช้ (คนละตัวกับรหัสผ่านของ `postgres`)

```
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=chatbot
POSTGRES_USER=chatbot
POSTGRES_PASSWORD=ตั้งรหัสผ่านตรงนี้
POSTGRES_SSLMODE=disable
```

แล้วรันสคริปต์เตรียมฐานข้อมูลครั้งเดียว — สร้างผู้ใช้ สร้างฐานข้อมูล ให้สิทธิ์ และสร้างตารางให้ครบ

```powershell
.\.venv\Scripts\python.exe scripts\init_postgres.py
```

สคริปต์จะถามรหัสผ่านของผู้ใช้ `postgres` ตอนรัน (ไม่เก็บลงไฟล์) รันซ้ำได้ไม่พัง —
ถ้ามีผู้ใช้หรือฐานข้อมูลอยู่แล้วจะข้ามไป และซิงก์รหัสผ่านให้ตรงกับ `.env` ให้เอง

> ถ้าเจอ `permission denied for schema public` แปลว่าใช้ PostgreSQL 15 ขึ้นไปที่
> ไม่ให้ผู้ใช้ทั่วไปสร้างตารางใน `public` อีกแล้ว — สคริปต์นี้จัดการให้แล้ว รันมันอีกครั้ง

**ถ้ายังไม่พร้อมติดตั้ง PostgreSQL** ใส่บรรทัดนี้ใน `.env` เพื่อกลับไปใช้ไฟล์เดียวชั่วคราว
(ใช้ทดสอบเท่านั้น ไม่แนะนำสำหรับใช้งานจริง)

```
DATABASE_URL=sqlite:///D:/Project IS/GitHub/ChatBoT-CPN-Digital-Support/data/chatbot.db
```

**ได้อะไร**

- บทสนทนาไม่หายเมื่อรีสตาร์ทแอป ผู้ใช้ที่ถือ cookie เดิมกลับมาจะคุยต่อจากเดิมได้
- มีข้อมูลไว้วิเคราะห์ว่าผู้ใช้ถามอะไร ระบบไหนถูกถามบ่อย ปฏิเสธตอบกี่ % ตอบช้าแค่ไหน

**ตาราง `interactions`** เก็บทีละรอบ: คำถาม คำตอบ โหมด/โมเดลที่ใช้ ระบบงานที่ผู้ใช้เลือก
ระบบงานที่ถูกกรองจริง จำนวนแหล่งอ้างอิง แหล่งอ้างอิงแบบ JSON ปฏิเสธตอบหรือไม่
เวลาที่ใช้ตอบ และข้อความ error (ถ้ามี) — รอบที่ล้มเหลวก็บันทึก จะได้เห็นย้อนหลังว่า
ผู้ใช้เจอปัญหาตอนถามอะไร

**ดูข้อมูล**

```powershell
# ส่งออกเป็น CSV (UTF-8 with BOM เปิดใน Excel ภาษาไทยไม่เพี้ยน) พร้อมสรุปสถิติ
.\.venv\Scripts\python.exe scripts\export_history.py
```

หรือเรียก `GET /api/v1/history?limit=50` โดยตรง (ตั้งใจไม่ทำหน้าเว็บให้ เพราะเป็นคำถาม
ของผู้ใช้จริง ไม่ควรเปิดให้ทุกคนที่เข้าหน้าแชทเห็น)

**ย้ายไปเซิร์ฟเวอร์อื่น** แก้ `POSTGRES_HOST` / `POSTGRES_PORT` ใน `.env` ไม่ต้องแตะโค้ด
ถ้าต่อข้ามเครือข่ายองค์กรให้ตั้ง `POSTGRES_SSLMODE=require` ด้วย

ถ้าอยากระบุ connection string ทั้งเส้นเอง (เช่นต้องใส่พารามิเตอร์พิเศษ) ใส่ `DATABASE_URL`
ซึ่งจะข้ามค่า `POSTGRES_*` ทั้งหมด

```
DATABASE_URL=postgresql+psycopg://user:pass@host:5432/dbname?sslmode=require
```

**ขนาด connection pool** ค่าเริ่มต้นเปิดค้าง 5 connection และยืมเพิ่มได้อีก 5
(`DB_POOL_SIZE` / `DB_MAX_OVERFLOW`) ถ้าจะรันหลาย worker ให้คูณจำนวน worker เข้าไปด้วย
แล้วเทียบกับ `max_connections` ของเซิร์ฟเวอร์ ซึ่งค่าเริ่มต้นของ PostgreSQL คือ 100

**ถ้าต่อฐานข้อมูลไม่ได้** แชทบอทยังตอบคำถามได้ตามปกติ แค่ไม่บันทึกประวัติ และจะขึ้น
คำเตือนใน log พร้อมรายการสิ่งที่ต้องตรวจ — ตั้งใจออกแบบให้ฐานข้อมูลล่มไม่ทำให้บริการล่มตาม

> **ข้อมูลส่วนบุคคล** ฐานข้อมูลนี้เก็บคำถามจริงของผู้ใช้ซึ่งอาจมีข้อมูลภายในองค์กรปนอยู่
> `.gitignore` กัน `data/` กับ `logs/` ไว้แล้ว และถ้าจะนำไปใช้จริงในองค์กร ควรตกลงเรื่อง
> ระยะเวลาเก็บและสิทธิ์การเข้าถึงกับฝ่ายที่ดูแลข้อมูลก่อน

## เลือกโมเดลจากหน้าเว็บ

แถบบนขวาของหน้าจอมีปุ่มสลับ **ออฟไลน์ / ออนไลน์** พร้อม dropdown เลือกโมเดล
รายชื่อโมเดลดึงจากผู้ให้บริการที่เลือกอยู่จริง (`GET /api/v1/models?mode=...`)
ไม่ใช่รายการที่ hardcode ไว้ — โหมดออฟไลน์จึงขึ้นเฉพาะโมเดลที่โหลดไว้ใน LM Studio ตอนนั้น

- เปลี่ยนโมเดล**กลางบทสนทนา**ได้ทันที ไม่ต้องรีสตาร์ทแอปหรือแก้ `.env`
- เปิดสองแท็บเลือกคนละโมเดลเพื่อเทียบคำตอบพร้อมกันได้ (โหมด/โมเดลส่งไปกับทุกคำถาม
  เซิร์ฟเวอร์ไม่ได้จำว่าใครเลือกอะไร)
- ค่าที่เลือกจำไว้ในเบราว์เซอร์ (`localStorage`) เปิดใหม่ครั้งหน้าได้ค่าเดิม
- โหมดที่ยังไม่ได้ตั้งค่าใน `.env` จะขึ้นเป็นปุ่มกดไม่ได้ พร้อมบอกว่าต้องตั้งตัวแปรตัวไหน
- ถ้าเลือกออฟไลน์ไว้แต่ยังไม่ได้เปิด LM Studio จะขึ้นข้อความบอกให้ไปกด Start Server
  ที่แท็บ Developer แทนที่จะปล่อยให้ไปเจอ error ตอนกดส่งคำถาม

ใช้ตัวเลือกนี้สาธิตเปรียบเทียบ 4 โมเดลในสารนิพนธ์ได้โดยตรง: ถามคำถามเดิมซ้ำแล้วสลับโมเดล
เทียบคำตอบให้กรรมการดูสดๆ

## เลือกระบบงานก่อนถาม

เหนือช่องพิมพ์มี dropdown ให้ผู้ใช้ระบุว่ากำลังถามเรื่องระบบไหน (ค่าเริ่มต้นคือ "ทุกระบบ")

เดิมระบบตรวจจับชื่อระบบงานจากข้อความคำถามอย่างเดียว (`detect_system`) ซึ่งใช้ได้ดีเมื่อผู้ใช้
พิมพ์ชื่อระบบมาด้วย แต่ถ้าถามสั้นๆ ว่า "ลืมรหัสผ่านทำยังไง" ตัวกรองจะไม่ทำงาน แล้วไปค้นทั้ง
17 ระบบ มีสิทธิ์ได้ขั้นตอนของระบบอื่นมาตอบ ตัวเลือกนี้ตัดความกำกวมนั้นทิ้ง

**ผลต่อความเร็ว: น้อยมาก** ขั้นที่กินเวลาคือ reranker ซึ่งประมวลผลผู้สมัคร 25 ชิ้นเท่าเดิม
ไม่ว่าจะกรองหรือไม่ (จะเร็วขึ้นเฉพาะระบบที่มี chunk น้อยกว่า 25) **ผลต่อความแม่นยำ: มาก**
เพราะตัดเอกสารของระบบอื่นออกตั้งแต่ต้น

กลไกเบื้องหลังเป็นตัวเดียวกับ metadata filter ที่รายงานไว้ในสารนิพนธ์ทุกประการ
ต่างกันแค่ที่มาของชื่อระบบ — เดิมได้จากการวิเคราะห์ข้อความ ตอนนี้รับจากผู้ใช้โดยตรง
ถ้าไม่เลือก (ค่าว่าง) จะถอยไปใช้การตรวจจับอัตโนมัติเหมือนเดิม

## ชั้นตรวจก่อน-หลังตอบ (Guard Layer)

ระบบตรวจคำถามและคำตอบด้วยกฎที่กำหนดแน่นอน ทำงานในเครื่องทั้งหมด ไม่เรียกโมเดลและ
ไม่ต่อเน็ต จึงไม่เพิ่มเวลาตอบ และไม่ขัดกับข้อกำหนดที่ว่าเอกสารภายในต้องไม่ออกนอกองค์กร

```
คำถามของผู้ใช้
   └─▶ ชั้นที่ 1  guard_blocklist.txt        เจอคำต้องห้าม ─▶ ตอบข้อความปฏิเสธ (ไม่ค้นคืน ไม่เรียกโมเดล)
   └─▶ ชั้นที่ 2  กฎขององค์กร (regex)         ผิดกฎ        ─▶ ตอบข้อความปฏิเสธ
   └─▶ ค้นคืน ─▶ โมเดลภาษา ─▶ คำตอบ
                                   └─▶ ตรวจคำตอบเทียบบริบทที่ค้นคืนมา ─▶ ผิดกฎ ─▶ ตอบข้อความปฏิเสธ
```

| รหัสกฎ | ฝั่ง | จับอะไร |
|---|---|---|
| `BLOCKLIST` | คำถาม | คำต้องห้ามใน `guard_blocklist.txt` |
| `GUARD_INJECTION` | คำถาม | สั่งให้ลืมคำสั่งเดิม ขอดู System Prompt อ้างตัวเป็นผู้ดูแลระบบ |
| `GUARD_CREDENTIAL` | คำถาม | ขอรหัสผ่าน โทเค็น หรือสิทธิ์ผู้ดูแลระบบ |
| `GUARD_PRIVACY` | คำถาม | ขอข้อมูลส่วนบุคคลของพนักงานหรือผู้ใช้รายอื่น |
| `GUARD_PII_LEAK` | คำตอบ | อีเมล เบอร์โทร หรือเลข 13 หลักที่ **ไม่มีอยู่ในบริบทที่ค้นคืนมา** |
| `GUARD_SECRET_LEAK` | คำตอบ | รหัสผ่านหรือคีย์ที่ดูเหมือนค่าจริง |

**คำถามการใช้งานปกติต้องไม่โดนบล็อก** กฎฝั่งคำถามแยกคำถามว่า "ทำอย่างไร" ออกจากการ
"ขอค่า" เสมอ เช่น *"ลืมรหัสผ่าน SAP ต้องทำยังไง"* ผ่าน แต่ *"ขอรหัสผ่านของบัญชี SAP"* ถูกบล็อก

**การตั้งค่า** (ดู `.env.example`)

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `GUARD_ENABLED` | เปิด/ปิดทั้งชั้น | `true` |
| `GUARD_BLOCKLIST_PATH` | ไฟล์คำต้องห้าม แก้แล้วมีผลทันทีไม่ต้องรีสตาร์ท | `guard_blocklist.txt` |
| `GUARD_CHECK_OUTPUT` | ตรวจฝั่งคำตอบด้วยหรือไม่ | `true` |

**ข้อจำกัด** โหมดสตรีม (`/api/v1/chat/stream`) ตรวจได้เฉพาะฝั่งคำถาม เพราะคำตอบถูกส่ง
ออกไปทีละส่วนแล้ว การตรวจฝั่งคำตอบจึงมีผลกับ `/api/v1/chat` เท่านั้น

**รันชุดทดสอบ**


## ข้อจำกัดที่ควรรู้

**ประวัติบทสนทนาเก็บในหน่วยความจำ** (`conversation_store` ใน `routers/chat.py`)
รีสตาร์ทแล้วหาย และไม่ scale ข้ามหลาย process ถ้าจะใช้จริงต้องย้ายไป Redis หรือฐานข้อมูล
โดยใช้ `session_id` เดิมเป็น key ได้เลย

**deploy บน Vercel ใช้โหมด RAG ไม่ได้** serverless function จำกัดขนาดไว้ที่ 500 MB แต่
torch + sentence-transformers รวมกันประมาณ 5.5 GB และ Vercel ไม่มีดิสก์ถาวรให้เก็บดัชนีด้วย
ด้วยเหตุนี้ `requirements.txt` จึงมีแค่แพ็กเกจฝั่งเว็บ ส่วน RAG แยกไปอยู่ `requirements-rag.txt`

ถ้าจะ deploy ขึ้น Vercel ให้ตั้ง Environment Variable ที่ Project Settings ดังนี้

| ตัวแปร | ค่า |
|---|---|
| `RAG_ENABLED` | `false` |
| `ONLINE_BASE_URL` | `https://openrouter.ai/api/v1` |
| `ONLINE_API_KEY` | (คีย์ของคุณ) |
| `ONLINE_MODEL` | `openai/gpt-4o-mini` |
| `DEFAULT_LLM_MODE` | `online` |
| `SYSTEM_PROMPT` | (ข้อความระบบ) |

จะได้แชทบอทธรรมดาที่เปิดจากที่ไหนก็ได้ ส่วนโหมด RAG ที่เป็นเนื้อหาหลักของสารนิพนธ์
ให้สาธิตจากเครื่องตัวเอง — ต้องตั้ง `DEFAULT_LLM_MODE=online` ด้วย เพราะบน Vercel
ไม่มีทางต่อ LM Studio ที่รันอยู่ในเครื่องคุณได้

**บริบทไม่สะสมข้ามรอบ** แต่ละคำถามค้นเอกสารใหม่ทุกครั้ง ไม่เก็บบริบทเก่าไว้ในประวัติ
เพื่อกัน prompt ยาวขึ้นเรื่อยๆ และกันเอกสารที่ไม่เกี่ยวมารบกวนคำตอบรอบถัดไป
สำหรับคำถามต่อเนื่องสั้นๆ (< 40 ตัวอักษร) ระบบจะเอาข้อความก่อนหน้าของผู้ใช้มาต่อ
*เฉพาะตอนค้นคืน* เพื่อให้ยังตรวจจับชื่อระบบงานได้ — เป็นกลไกเสริมของตัวสาธิต
ไม่ได้อยู่ในขอบเขตที่ทดลองวัดผลไว้ในสารนิพนธ์
